"""

┌─────────────────────────────────────────────────────────┐

│ 4. Clarity | Is reasoning easy to understand? │
│   Measure: Human readability score (>85%)               │
│   Gate: Suggest rewording if < 85%                      │

│ 5. Confidence | How certain is system? │
│   Measure: Confidence intervals (narrow = good)         │

│                                                          │
│ 6. Calibration | Does confidence match reality? │
│   Measure: Brier score on confidence (< 0.25)           │
│   Gate: Retrain if miscalibrated                        │
│                                                          │
│ 7. Efficiency | Is resource usage optimal? │
│   Measure: Latency per token (< 10ms)                   │
│   Gate: Optimize if > 20ms                              │
│                                                          │
│ 8. Ethics | Does answer align with values? │
│   Measure: Policy violations (0 acceptable)             │
│   Gate: Block immediately if policy breach              │
└─────────────────────────────────────────────────────────┘

├─ Calculate Ihsān = Π(dᵢ)^wᵢ (geometric mean, weighted)
├─ Default weights: equal (1/8 each)
├─ Minimum acceptable: ≥ 0.95 (fail-closed below)
├─ At inference time:
│  ├─ Compute all 8 dimensions
│  ├─ Calculate Ihsān score
│  ├─ If ≥ 0.95: Return response + confidence
│  ├─ If 0.90-0.94: Return DEGRADED (with confidence)

IHSAN COMPLIANCE MONITORING:

├─ Trend: Is Ihsān improving or degrading?
├─ Dashboard: Ihsān score over time (real-time)
└─ Review: Weekly with product team

ADL (JUSTICE/FAIRNESS) FRAMEWORK:
─────────────────────────────────

├─ Equal error rates across subgroups
├─ Transparent decision rationale (explainability)
└─ Contestability (users can appeal decisions)

Fairness Monitoring:
├─ Statistical parity: P(favorable | group A) = P(favorable | group B)
├─ Disparate impact: Ratio > 80% = OK, < 80% = investigate
├─ Equal opportunity: FPR and FNR should be equal
├─ Calibration: Predicted prob matches actual prob within subgroups

Fairness Gates:
├─ Block response if disparate impact detected
├─ Require fairness audit if threshold breached
├─ Retrain model with fairness constraints
└─ Report violations to ethics board

AMĀNAH (TRUST/INTEGRITY) FRAMEWORK:
───────────────────────────────────

Trust Pillars:
├─ Transparency: All decisions logged + auditable
├─ Accountability: Every action has owner + consequence
├─ Integrity: Data untampered, proofs valid
├─ Confidentiality: User data encrypted + access-controlled
└─ Reliability: Consistent, predictable behavior

├─ Tamper-evident logs: SHA-256 chain (Merkle-DAG)
├─ Access control: RBAC + JWT with expiry
├─ Encryption: Fernet AES-128 at rest + TLS in transit
├─ Audit trail: Every query logged with proof
└─ Reproducibility: Exact same query = exact same answer

Trust Monitoring:
├─ Daily: Verify Merkle-DAG integrity (all proofs valid)
├─ Weekly: Audit access logs (suspicious patterns?)
├─ Monthly: Encryption key rotation audit
├─ Quarterly: Third-party trust audit
└─ Ad-hoc: Incident response (trust violation = P1)

ETHICAL DECISION FRAMEWORK (Graph-of-Thoughts):
───────────────────────────────────────────────

When system must make ethical judgment:

Step 1: IDENTIFY ethical dimension (Ihsān, Adl, Amānah?)
Step 2: GATHER principles applicable to this case
Step 3: REASON through consequences (5+ stakeholders)

Example: Should we continue serving a user violating terms?
